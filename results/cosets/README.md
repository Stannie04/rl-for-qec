# Logical coset catalogue

Generated by `src/train_utils/coset_catalogue.py`:

```bash
python src/train_utils/coset_catalogue.py --code 144_12_12_ldpc --max-weight 14
```

(Run the file directly: importing it through the `src.train_utils` package pulls in torch/galois.)

## What is a coset here?

For a CSS code with `k` logical qubits, an X-type error `e` that commutes with every Z check
(`H_z e = 0`) is either a stabiliser or a logical operator. Its **coset** is its logical
syndrome `s = Lz e` in `F2^k`, where `Lz` are the Z logical operators. All errors with the
same `s` differ by a stabiliser and are equivalent for decoding.

The gross code has `k = 12`, so there are `2^12 - 1 = 4095` non-trivial X-type cosets
(the Z-type ones are the mirror image under swapping the A and B polynomials). The coset id
in the files is `s` read as a binary number (bit `i` = logical qubit `i`).

## Minimum weight

For each coset we want the lightest error in it. That is an exact integer program
(HiGHS via `scipy.optimize.milp`, zero gap):

    minimise |e|   s.t.   H_z e = 0,   Lz e = s   (mod 2),   |e| <= max_weight

The cap (default 14) keeps the run feasible. A coset with no representative of weight
`<= max_weight` is only marked **above** (proved), or **unknown** if the per-solve time
limit hit. Code distance is 12, so no coset is lighter than 12.

## Orbits

The `6 x 12` torus translations are symmetries of the code (72 shifts). Shifting a
representative of coset `c` gives a representative of some other coset `c'` with the
same weight and the same shape. All cosets reached this way form one **orbit**.

- The MILP is solved once per orbit; the rest of the orbit is obtained by shifting.
- Orbit size is `72 / (number of shifts that fix the coset)`, so it is at most 72 and
  often smaller (e.g. 36 or 12).
- Each panel in `lowest_weight.png` is one orbit, titled `w=<weight> xN` (minimum weight,
  number of cosets in the orbit).
- Only translations are used. Further code symmetries (e.g. A <-> B swap) would merge
  some orbits, so the number of distinct patterns could be a bit smaller.

## Files in `<code>/`

| file | content |
|------|---------|
| `catalogue.npz` | per coset: `coset` id, `rep` (0/1 vector, L block then R block), `weight` (`-1` above cap, `-2` unresolved), `orbit`, `status` |
| `catalogue.csv` | one row per orbit: weight, number of cosets, support of a shifted-to-compact representative |
| `lowest_weight.png` | one tiny-dot panel per orbit at weight `<= max_weight`; blue = L qubit, orange = R qubit |
| `enum_catalogue.csv` | from `coset_enumerate.py` (information-set sampling): one row per orbit found, lightest weight found (upper bound; exact at 12 = d), orbit size, number of distinct words, support |
| `enum_lowest.png` | panels of the sampled orbits, same style as `lowest_weight.png` |
| `enum.npz` | sampler checkpoint (all distinct words found, ~30 MB); not committed, regenerate with the command below |

Sampling run used for `docs/logical_errors/` (about 4 min):

```bash
python src/train_utils/coset_enumerate.py --code 144_12_12_ldpc --max-weight 16 --trials 20000 --workers 2
```

Qubit index `q`: `q < 72` is an L qubit, `q >= 72` an R qubit; within a block
`q % 72 = a*12 + b` is site `(a, b)` of the `6 x 12` torus (`x^a y^b`).
